# 库街区探索助手 v0.1.0

鸣潮（Wuthering Waves）大地图探索辅助桌面工具：把**公开地图点位**画在高清大地图上，记录**你本人**的探索进度，
可选用**屏幕像素识图**估算你在地图上的位置。Windows 桌面程序（PySide6 / Qt6），不读游戏内存、不注入进程、不模拟键鼠。

- 适用平台：Windows 10 / 11（macOS / Linux 可跑开发模式，但全局热键、DPAPI、系统托盘这三处会退化）
- 运行环境：Python 3.10+（推荐 3.12）
- 版本：`0.1.0`（`src/kumap/__init__.py` 中的 `__version__`）

## 这是什么 / 这不是什么

**能做：**

| 分类 | 功能 |
| --- | --- |
| 地图与点位 | 加载高清大地图；滚轮以光标为中心缩放、拖拽平移；六个图层独立开关 + 一键全显/一键全隐；不同图层不同形状与颜色图标；仅绘制可视范围内的点位 |
| 进度记录 | 手动标记点位「已完成」（图标变暗 + 勾）与一键隐藏已完成；右键自建私人点位并写备注；悬浮 tooltip 显示名称/图层/掉落/玩家备注/来源/坐标；搜索框按名称与备注过滤 |
| 路线 | 玩家路线绘制为轨迹线并逐步编号；顺序导航（自动定位下一站 + 上一个/下一个 + 图上距离）；路线可收藏（★）、「只看收藏」、随时切换加载 |
| 识图定位（可选） | 本地截屏取游戏小地图像素 → OpenCV 特征匹配在大地图上估算玩家位置并实时打点；间隔 500ms~10s 可调、随时开关；自动检测圆形小地图或手选固定区域；严格度可调；连续失败自动降频并提示改用手动定位 |
| 界面 | 全局快捷键（游戏内免 Alt-Tab）、窗口置顶、不透明度调节、锁定窗口尺寸、紧凑小窗（430×300）、最小化到系统托盘、关闭到托盘、深色/浅色主题 |
| 账号（需官方端点配置） | 跳转**库街区官方授权页**登录/扫码，拉取本人已完成的宝箱/锚点/材料/声骸/解谜/任务标记并显示为已完成；工具内标记可一键回传账号（冲突策略：以较新为准 / 以云端为准） |

**不做（硬性边界，详见 [docs/合规说明.md](docs/合规说明.md)）：** 不读取游戏进程内存、不注入 DLL、不 Hook 游戏消息、
不修改任何游戏数据、不自动点击/自动寻路/自动战斗、不采集账号密码、不抓取私有接口、不逆向。

## 合规与免责

程序内合规声明（与 `src/kumap/__init__.py` 的 `COMPLIANCE_STATEMENT` 逐字一致，首次启动会弹出确认）：

> 本工具是纯粹的探索参考辅助：只展示公开地图数据、记录你本人的标记进度，并通过屏幕像素识别估算当前位置。它不读取游戏内存、不注入进程、不修改游戏数据、不模拟任何键鼠操作，因此不属于外挂程序。识图定位存在误差，仅作探索参考，不保证识别结果完全准确。请遵守《鸣潮》用户协议与库街区社区规范使用本工具。

免责原文（请务必知悉）：

> 识图定位存在误差，本工具仅为探索参考辅助，不保证识别结果完全准确

**数据口径（重要，先读再用）：** 仓库内置的点位、路线与底图全部是**示例数据**（`source = "sample"`，
底图是程序自绘的占位图），只用来演示界面与流程，**不是**库街区大地图的真实坐标。
要拿到与库街区大地图一致的点位，请把官方或社区**公开导出**的数据包放进 `import/` 目录，
并且**底图必须与点位数据同一来源、同一尺寸**，否则点位会整体偏移。见 [数据导入](#数据导入换成真实点位与底图)。

游戏名称、素材/声骸等名词与地图美术版权归广州库洛科技有限公司所有；本项目仅作知识性引用，不携带官方美术资源与未公开数据。

## 环境与安装

1. 安装 **Python 3.10+（推荐 3.12）**：https://www.python.org/downloads/windows/ ，安装时勾选 **Add python.exe to PATH**。
2. 下载/解压本项目到任意目录（路径含中文、空格都可以）。
3. 安装依赖二选一：
   - 双击 / 命令行运行 `run_dev.bat`（自动建 `.venv` 并装依赖，推荐）；
   - 手动：
     ```bat
     cd 项目目录
     py -3 -m venv .venv
     .venv\Scripts\python.exe -m pip install -r requirements.txt
     ```
4. 想要「屏幕识图定位」再装可选依赖（不装也能用，功能自动禁用）：
   ```bat
   .venv\Scripts\python.exe -m pip install -r requirements-dev.txt
   ```

依赖分组见 `requirements.txt`（必需 = PySide6；可选 = opencv-python / numpy / mss，仅识图需要；
cryptography 只在非 Windows 开发环境做凭证加密回退）与 `requirements-dev.txt`（测试 + 打包 + 识图）。

## 快速开始

### 开发运行（源码直接跑）

```bat
cd 项目目录
run_dev.bat
```

默认以**内置官方浏览器大地图为主界面**：主窗口不显示，官方地图窗口打开。想临时回本地地图，
点官方窗口「主窗口」，或以 `run_dev.bat --local-map` 启动；「探索向导」用 `run_guide.bat`。

等价的手动命令（cmd）：

```bat
set PYTHONPATH=src
.venv\Scripts\python.exe -m kumap.main
```

`python -m kumap`（走 `src/kumap/__main__.py`）效果相同。PowerShell 里设置环境变量的写法不同：

```powershell
$env:PYTHONPATH = "src"
python -m kumap.main
```

命令行参数（`src/kumap/main.py` 已实现）：

| 参数 | 作用 |
| --- | --- |
| `--data-dir <目录>` | 便携模式：配置、进度、令牌都写到指定目录 |
| `--no-tray` | 不在系统托盘常驻 |
| `--reset-view` | 复位窗口尺寸与位置（清掉记住的 geometry 与紧凑标记） |
| `--compact` | 以紧凑悬浮小窗（430×300）启动 |
| `--map-only` | 只打开内置官方浏览器地图；主窗口隐藏，识图/路线在官方窗口工具栏操作 |
| `--local-map` | 启动时显示本地主窗口（临时想用本地地图时） |
| `--guide` | 探索向导：只开官方地图，按当前位置自动规划顺路路线并逐步指示 |
| `--version` | 打印版本后退出 |

例：`python -m kumap.main --no-tray --compact`

### 打包成 exe

```bat
build_windows.bat
```

脚本会装好 `requirements-dev.txt` 后执行 `pyinstaller packaging\kumap.spec --noconfirm`。产物：

```
dist\KuroMapHelper\KuroMapHelper.exe        ← 默认（ASCII 名，双击即可运行）
dist\KuroMapHelper\_internal\...            ← Qt 运行库与内置示例数据，必须一起保留
```

spec 默认使用 ASCII 产物名，避免个别 Windows 环境/杀软对非 ASCII 路径的兼容问题。想交付
**`库街区探索助手.exe`**，在打包前设置环境变量（`packaging/kumap.spec` 会读取）：

```bat
set "KUMAP_EXE_NAME=库街区探索助手"
build_windows.bat
```

产物即 `dist\库街区探索助手\库街区探索助手.exe`。也可以直接把 spec 里 `APP_NAME` 的默认值改成中文名。
exe 名字不影响数据目录（始终是 `%APPDATA%\KuroMapHelper`）。

**交付时要拷贝整个 `dist\<名字>\` 文件夹**，单独拿 exe 会缺 Qt 运行库。若打包的机器上没装
opencv-python / numpy / mss，产出的 exe 只有「手动定位」，识图开关会自动禁用并提示。

### 游戏内悬浮指示（Overlay）

顶栏 `➤` 或 `Ctrl+Alt+O` 打开一个置顶、半透明、**鼠标可穿透**的小窗，放在主屏右下角：

- 圆圈内是以识图/手动位置为中心的官方底图（约 3.7km 视野）；
- 青色虚线是当前加载的路线，数字点是下一站；目标超出圆圈时在边缘显示方向箭头；

- 不挡鼠标点击、不写入游戏；需要游戏运行在**窗口化 / 无边框窗口**，全屏独占时置顶窗会被盖住。
- 官方账号进度同步在“官方原始地图”窗口内由官方页面完成；悬浮指示用的是本机路线与识图位置。

## 数据导入（换成真实点位与底图）

完整字段表与最小示例见 **[docs/数据格式说明.md](docs/数据格式说明.md)**。

1. 打开本机数据目录：设置 → 数据与地图 →「打开本机数据 / import 目录」（即 `%APPDATA%\KuroMapHelper\import`）。
2. 把官方/社区**公开导出**的点位包放进来，命名规范：
   - `points_*.json`：主点位文件（多个时**文件名倒序 = 最新优先**，只有第一个当主文件，其余当分片）；
   - `routes_*.json`：路线文件（按文件名倒序逐个读取，同 `id` 以**先读到的**为准 = 最新导入包优先；内置示例最后读，只补充没被占用的 `id`）；
   - `world_map.png`：与点位同源的底图；
   - 目录内**其它** `*.json`（不以 `routes` 开头）会被当作点位分片按 id 合并进主数据集。
3. 重启程序即可加载；也可以在 设置 → 数据与地图 里直接指定「点位数据文件」与「大地图底图」（优先级最高）。

**优先级（与 `core/provider.py` 实现一致）：**

- 点位：`1) 设置指定的 points 文件（最高） → 2) import/points*.json（文件名倒序，第一个存在的就是主文件） → 3) 内置示例 points.json`；
  随后把 `import/` 下其它 `*.json`（不以 `routes` 开头）里的 points 按 `id` 合并：主文件是导入/手选文件时顺序为
  `主文件 > 分片 > 内置示例`，主文件是内置示例时为 `分片 > 内置示例`；同一个 id 只保留先出现的那一份，
  `layers`/`regions` 缺失项一并补齐。**分片之间别用重复 id**（谁赢取决于文件名顺序）。
- 底图：`设置指定 > 数据包 map 字段/数据包同目录 world_map.png > import/world_map.png > 内置占位图`。
  注意 `map.image` 若要生效必须写**绝对路径**或相对内置资源目录的路径；把底图命名成 `world_map.png` 与点位文件放同一目录最省事。
- 路线：`import/routes*.json`（文件名倒序）逐个读取，之后才读内置示例 `routes.json`；同一个 `id` **以先读到的为准**，
  所以导入包里的路线会盖掉内置示例的同 id 路线（与点位同一套口径）。设置里没有路线文件的手选项，只能靠 `import/` 目录。

**底图同源要求（最容易踩的坑）：** 点位 `x/y` 是相对底图宽高的 0~1 归一化值。若用 A 站点导出的点位配 B 尺寸的底图，
所有点位会整体缩放/偏移。请务必让**点位与底图来自同一份导出**；程序不会替你换算。

示例数据不是摆设：导入失败或数据文件损坏时程序会回退/报错到日志，示例包始终保留可一键回到干净状态
（把 `import/` 里的文件移走即可）。

### 用官方大地图的公开资源自动生成数据包（`tools/fetch_official_map.py`）

> 该脚本生成 state 8 的整张拼合图，适合自检/研究；正式使用推荐下面的「四国地图包」，避免四国混在一张图里。

库街区 H5 大地图的**图片瓦片与点位 JSON 都是匿名可访问的静态文件**（任何人打开
`https://www.kurobbs.com/mc/map/` 都会发同样的请求），所以**不需要登录、不需要任何账号**就能把它们本地化。
仓库里带一个一次性抓取脚本，跑完就把官方底图和官方点位变成上面 `import/` 目录里的数据包：

```bat
cd /d 项目目录
set PYTHONPATH=src
python tools\fetch_official_map.py --dry-run          :: 先看规模，不下任何东西
python tools\fetch_official_map.py                   :: 正式抓取（会先报请求数并询问确认）
```

产物（默认写进 `%APPDATA%\KuroMapHelper\import`，用 `--data-dir` 可改）：

| 文件 | 内容 |
| --- | --- |
| `world_map.png` | 按官方瓦片网格拼好的整张同源底图 |
| `points_kurobbs_<state>.json` | 官方点位（当前 state=8 约 1.92 万个）转成本工具图层，另存原始世界坐标 `world` |
| `kurobbs_meta.json` | 出处、抓取时间、资源 id、瓦片网格与坐标换算参数 |
| `kurobbs_cache/` | 瓦片与原始 JSON 缓存：重跑只补没下过的，**别把它当备份删掉** |

常用参数：`--state` 地图版本（官方当前 8）；`--ee` 手工指定地图资源 id（默认自动查一次并缓存到
`kurobbs_cache/resource_id.txt`，官方大版本更新后删掉该文件重跑即可）；`--scope all|near` + `--near N`
（`near` 只下有点位的格子及其邻域，省一大半流量）；`--tile-width 32|64|128|256|512|1024`（官方源片 1024，只能降采样）；
`--delay` 请求间隔（默认 0.25s，请不要调小）；`--max-tiles` 安全阀（默认 900）；`--skip-tiles` 只更新点位；
`--keep-points-json` 只更新底图、不覆盖你自己的点位包；`--limit N` 连通性自检；`--yes` 非交互。

**tile-width 怎么选：** 官方 state=8 的内容包络是 28×28 格。`128` → 3584×3584 像素（约 20~30MB，看着清楚，内存占用也高）；
`64` → 1792×1792；`32` → 896×896。识图定位的世界索引上限是 **1400 像素**（`core/recognizer.py` 的 `INDEX_MAX_DIM`），
超过就会被进一步降采样，特征变少、成功率下降。所以：**主要靠识图 → `--tile-width 32` 全图，或 `64` 配 `--scope near`**；
主要在屏幕上读点位、看清细节 → `128`（1792 以上的整图靠手动定位或局部识图，别指望全图识图很准）。

**必须知道的边界：**

- 抓下来的东西**版权归库洛游戏/鸣潮官方**，只能个人学习研究，**不得二次分发、不得商用**，
  也不要把它打进任何安装包；`import/` 已在 `.gitignore` 里，别提交。
- 这是**低频一次性操作**。抓完就长期离线用，别写进计划任务反复敲官方 CDN（脚本自身限速、并优先用缓存）。
- 点位坐标来自官方数据，**只用于地图显示**；本工具不会把坐标反查成角色位置，也不做自动寻路、不自动点击。
  官方数据里那个孤零零的飞点会被自动剔除（详见 `kurobbs_meta.json` 的 `outliers`）。
- 数量分布（state=8 实测，共 19249 点）：采集物 9434、敌人 5972、宝箱·收集物 2978、挑战·解谜 712、
  BOSS·声骸 104、信标·服务点 49。全图开着一半以上图层会很挤，按需用侧栏图层开关关掉；
  点位多不会拖慢刷新（画布会自动降级聚合，见「已知限制」第 8 条）。
- 卸载方式很简单：把 `import/` 里这几个 `kurobbs`/`world_map.png` 文件移走，程序自动回到内置示例数据。

## 账号登录与云端同步

> **诚实说明（当前状态）：** 截至目前，**库街区没有公开、有文档的第三方 OAuth 授权端点与大地图读取接口**。
> 因此「云端拉取/回传」在本工具里是一个**已实现但需要官方端点配置**的适配器（`core/provider.py` 的 `KuroApiProvider`）。
> 未配置时相关按钮会提示「未配置」，**无账号模式与全部本地功能完全可用**；本工具不抓取私有接口、不逆向、不采集账号密码。

**登录流程（全程在官方页面完成）：**

1. 侧栏「库街区账号」→「官方授权登录」→ 弹出说明页，点「打开官方授权页面」，系统浏览器打开**库街区官方**授权页；
   「库街区账号」分组里还有「退出登录」「拉取云端」「回传云端」「双向同步」四个按钮；未登录时该分组显示
   「未登录 · 无账号模式」，并固定提示「本地进度不会离开本机」。
2. 手机号验证码登录 / 扫码都在官方页面进行 —— **本工具没有任何账号密码输入框**，也接收不到、不记录凭据；
3. 授权采用 OAuth2 授权码 + PKCE（S256）+ `state` 校验；官方页面把一次性授权码回调到本机
   `http://127.0.0.1:8756/callback`（仅回环监听、校验通过立即关闭，等待上限 180 秒）；
4. 工具用授权码 + `code_verifier` 到官方 token 端点换 access/refresh token，令牌经 **Windows DPAPI** 加密后只存本机
   （`credentials.bin`，权限 0600），不经过任何第三方服务器；**退出登录立即删除**；uid 只保留脱敏形式。
   授权范围仅 `map.markers.read` / `map.markers.write`。

**要真正联网，需要先配置官方端点**（你已获得官方授权许可的前提下）：设置 → 账号与同步，填

| 界面字段 | 对应 `kuro_api.json` 键 | 说明 |
| --- | --- | --- |
| 官方授权页 URL | `authorize_url` | 官方 OAuth2 授权页 |
| 官方 token URL | `token_url` | 官方令牌端点 |
| 云端标记读取 URL | `markers_url` | 读取本人大地图标记 |
| 云端标记回传 URL | `push_markers_url` | 回写本人标记 |
| client_id | `client_id` | 官方发放的应用标识 |
| 本机回调端口 | `redirect_port` | 默认 8756，被占用时可改 |

点「保存接口配置到 kuro_api.json」写入数据目录。界面未提供的可选字段（`userinfo_url`、`points_url`、`routes_url`、
`scopes`、`verify_tls`）可直接编辑 `kuro_api.json`；只填 `authorize_url` + `token_url` + `client_id` 才算「已配置」，
还需 `markers_url` 才会启用云端标记同步。所有请求限制超时 12 秒、响应 12 MB，且只允许 http/https。

**双向同步行为：**

- 拉取：云端已完成的宝箱/锚点/材料/声骸/解谜/任务标记在本工具里显示为已完成；登录后默认自动拉取
  （设置里「登录完成后自动拉取云端进度」勾选框可关）。
- 回传：工具内手动标记进入待回传队列（`markers.json` 的 `pending` 字段），点「回传云端」或「双向同步」发送。
  配置项 `sync.auto_push` 默认关闭，且当前设置界面没有暴露这个开关，因此**回传始终需要手动点按钮**。
- 冲突策略（设置 → 账号与同步）：「本地较新的改动优先（推荐）」（默认，保留本机未回传的改动）/「以云端为准」（丢弃本机未发送的改动）。
- 只上传点位的完成状态（`{"markers": [{"id": ..., "done": ...}]}`），不上传游戏内任何数据、不上传截图；
  你自建的私人点位若被勾选完成，回传的也只是它的 id（坐标仍只在本机 `private_points.json`）。

## 识图定位

原理：本地屏幕截图取游戏**小地图像素** → OpenCV 特征匹配在与点位数据同源的大地图里估算玩家位置、朝向与比例尺，
并在大地图上实时打点。**只读像素**：不读游戏内存、不注入、不 Hook。

引擎会按底图尺寸自动选择：

- 底图最长边 ≥ 2500px（官方 6144 底图）：使用 **SIFT**（尺度/旋转不变）。合成测试定位误差约 0.2‰，
  在纯色海面/黑区等无纹理画面会明确失败并**保留上一次位置**，不会退回可能误报的 ORB。
- 小图 / 内置示例底图：沿用 ORB + RANSAC 仿射。
- 换用官方数据包后不需要额外调「视野半径」；识图仍受 HUD 遮挡、天气、小地图样式影响，属探索参考级精度。

**开启步骤：**

1. 先确认已装识图依赖：`pip install opencv-python numpy mss`（`run_dev.bat` 默认只装 PySide6，故此项需手动加）。
   未安装时开关自动禁用，侧栏提示「识图组件不可用（缺少 OpenCV / 截屏依赖），请用手动定位」，其余功能不受影响。
2. 设置 → 识图定位：小地图区域取默认「自动在屏幕上寻找小地图边界」（自动检测圆形小地图），找不到时自动回退到
   「小地图区域」这四个比例值构成的固定矩形；也可以点「设为屏幕左上角 / 右上角」预设，
   或「框选屏幕区域（下一步在屏幕拖框）」（对话框最小化后在屏幕上按住鼠标拖出一个框）。
3. 识别间隔 500 ~ 10000 ms（默认 1500 ms，步进 250）；严格度 10 ~ 95（默认 55，数值越高越严格：不容易误判，但更容易判失败）。
   「在大图上保留最近识别轨迹点」默认开启。
4. 点「立即测试一次识别」验证，成功会打印坐标与置信度。
5. 顶栏 `👁` 或 `Ctrl+Alt+V` 开启/关闭。

**误差与兜底：**

- 界面常驻提示（侧栏固定文案「识图仅读取屏幕像素，存在误差，仅作探索参考。」，识图每次成功/失败后状态栏会补一句
  `识图定位存在误差，仅作探索参考，不保证识别结果完全准确。`）；HUD 遮挡、天气特效、地图素材差异都会造成偏差。
- 连续 3 次失败：自动降频（不低于 3 秒一次）省资源，并提示/切换到「手动点击大图定位」兜底
  （在大图上点一下你所在的位置即可，之后可继续标记、继续导航）。
- 失败原因会用可读文字告诉你（没识别到小地图 / 特征太少 / 置信度不足 / 截屏失败 / 底图未加载 / 缺少识图依赖）。
- 底图必须与点位数据同源，否则识图坐标与点位坐标不在同一张图上。

**隐私：** 截屏画面只在内存里做特征匹配，**不上传、不落盘**（代码里没有任何截图写文件路径），也不会被写进日志；
日志只记录识别耗时、内点数、置信度等统计量。识图需要读取整屏像素，因此请不要在包含敏感内容的界面开启它。

## 常见问题

**Q：快捷键按了没反应 / 提示注册失败？**
设置 → 全局快捷键 会逐条显示注册结果。`已被系统或其他程序占用` 就换一组组合键（例如 `Ctrl+Alt+Shift+M`）；
若显示「当前系统不支持全局热键」（非 Windows 或被禁用），只能用窗口内快捷键，需窗口在前台。
热键必须包含 Ctrl / Alt / Win 之一，纯字母组合会被拒绝注册，以免与游戏操作冲突。

**Q：点位整体偏移、和实际位置对不上？**
九成是**底图与点位数据不同源**（尺寸或坐标口径不同）。请让二者来自同一份导出；
或先在 设置 → 数据与地图 里手动指定与该点位包配套底图，重启后看效果。内置示例坐标不对应真实游戏位置，这是设计如此。

**Q：找不到 exe / 双击没反应？**
- 打包产物是 `dist\<APP_NAME>\` **整个文件夹**，主程序为 `dist\<APP_NAME>\<APP_NAME>.exe`（默认 `KuroMapHelper.exe`）；
  只拷贝 exe 会缺 `_internal\` 里的 Qt 运行库。
- 构建脚本只在成功时不暂停；失败会 `pause` 并给出中文原因，可回看上方 PyInstaller 输出。
- 部分杀软会拦新生成的 exe，请添加信任后重试。
- 双击闪退：看 `%APPDATA%\KuroMapHelper\app.log`（打包版无控制台窗口，异常都写这里）。

**Q：怎么彻底清除本机数据与令牌？**
1. 托盘右键 →「退出程序」（或直接结束进程，确保 `app.lock` 释放）；
2. 删除整个 `%APPDATA%\KuroMapHelper` 目录（含 `credentials.bin` 令牌密文、`markers.json` 进度、`kuro_api.json` 端点、`app.log`、`import\`）；
   便携模式则删除 `data\` 目录或 `--data-dir` 指向的目录；
3. 只想退出登录：设置 → 账号与同步 → 退出登录，会**立即**删除 `credentials.bin`，本地进度保留；
4. 程序目录（或 `dist\`）本身不含用户数据，删掉它不影响你的进度；反之只删程序目录不会清掉令牌与进度。
5. 只想复位窗口大小/位置：`python -m kumap.main --reset-view`。

**Q：登录按钮点了提示「未配置」？**
即上文所说：官方未公开第三方授权端点。填好官方端点（含官方发放的 `client_id`）才会真正联网；
在此之前请用无账号模式，或在库街区 App 内直接查看/编辑同一份进度。

**Q：识图一直失败？**
先确认底图与点位同源 → 在设置里用小地图区域预设或重新框选 → 降低严格度 → 用「立即测试一次识别」看原因 →
必要时直接用「手动标记我的位置」（侧栏识图分组，或空白处右键 → 把这里设为我的位置）。
注意识图截取的是主显示器画面：游戏跑在副屏时请先把它挪到主屏，或改用手动定位。

**Q：置顶了还是被游戏盖住？**
《鸣潮》需要运行在「窗口化 / 无边框窗口」模式，置顶悬浮窗才会浮在游戏之上；全屏独占模式下任何置顶窗口都会被遮挡
（设置 · 窗口与外观 里也有这条提示）。

```bat
cd 项目目录
run_dev.bat                                  :: 建 .venv + 装必需依赖 + 启动
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt   :: 再加测试/打包/识图依赖
```

| 目的 | 命令（在项目根目录） |
| --- | --- |
| 跑全部测试（cmd） | `.venv\Scripts\python.exe -m pytest tests -q`（项目根的 `conftest.py` 已把 `src` 加进 `sys.path`） |
| 只跑识图用例 | `.venv\Scripts\python.exe -m pytest tests\test_recognizer.py -q`（该文件自己也会把 `src` 加进 `sys.path`） |
| 无显示器环境跑测试 | Linux/macOS CI：`QT_QPA_PLATFORM=offscreen python3 -m pytest tests -q` |
| 重新生成示例点位/路线 | `python tools\gen_sample_data.py` |
| 重新生成占位底图 | `python tools\gen_placeholder_map.py`（需要 Pillow，见 requirements-dev.txt） |
| 打包 exe | `build_windows.bat` |

`tests/` 下除识图用例外，还有数据层（`test_core_data.py`：配置、标记存储、同步合并、本地数据源）与平台层
（`test_core_platform.py`：热键、加密存储、授权流程、合规静态扫描）两组用例，它们直接 `import kumap.core.*`。
项目根目录的 `conftest.py` 负责把 `src` 插进 `sys.path`、设 `QT_QPA_PLATFORM=offscreen`，并整个会话只建一个
`QApplication`，所以在项目根直接 `python -m pytest tests -q` 即可；如果绕开 conftest（例如在别的目录跑），
就要手动 `set PYTHONPATH=src`（`run_dev.bat` 已设置）。

- `tests/test_recognizer.py` 用内存合成画面跑识图算法，不需要真实游戏、也不需要显示器。
- `tools/gen_sample_data.py` 会按固定随机种子重建 `src/kumap/resources/data/points.json` 与 `routes.json`
  （336 点位 / 6 图层 / 8 区域；8 条路线 / 163 步），并在写盘前用断言校验数据契约（坐标范围、点落在所属区域、
  路线引用的 `point_id` 必须存在、首步必须是锚点等）；重复运行输出字节级一致。
- 源码为 src 布局，`kumap` 包的导入路径靠 `PYTHONPATH=src`（`run_dev.bat` 已设置）。

## 已知限制

1. **云端同步依赖官方端点配置**：库街区当前没有公开、有文档的第三方 OAuth 授权端点与大地图接口；
   未配置时云端功能显示「未配置」，本工具不自带任何私有接口地址、不做逆向抓取。
2. **内置数据是示例**：`source = "sample"`，坐标为程序生成的归一化值，与真实游戏位置无对应关系；底图为自绘占位图。
   需要真实点位可自行导入公开导出数据包（并保证底图同源同尺寸），或用 `tools/fetch_official_map.py`
   把库街区官方大地图的公开瓦片与点位本地化（约 1.92 万点，见「数据导入」一节）。
3. **识图有误差**：受 HUD 遮挡、天气/特效、小地图尺寸与底图素材影响，可能定位失败或偏移；已提供降频与手动定位兜底。
4. **平台差异**：全局热键、DPAPI 令牌加密、系统托盘行为以 Windows 为准；其他系统仅作开发调试用（热键退化为窗口内快捷键、
   令牌改用 PBKDF2+Fernet 回退）。
5. **单实例**：同一数据目录只允许一个实例，多开会被 `app.lock` 拦下。
6. **待回传队列位置**：队列写在 `markers.json` 的 `pending` 字段，`sync_queue.json` 目前只是预留路径。
7. **未做代码签名**：新打包的 exe 可能被 SmartScreen / 杀软提示，交付时请说明来源。
8. **探索向导的地下分层**：数据模型与规划已支持按 floor 分组，但当前离线四国包只有地上点位；
   地下/独立区域仍是官方 state 页面，位置叠加与离线路线暂不覆盖。
9. **点位多了会自动降级显示**：一帧图标数超过 2400 个时，画布按像素格聚合成小圆点（缩到全图时本来也糊成一团），
   悬浮与点击命中的仍是真实点位；官方数据包实测全览一帧约 25ms。底图超过 1400px 时识图索引会降采样，识别成功率下降。
