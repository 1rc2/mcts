# 数据格式说明（points.json / routes.json）

适用版本：`schema_version = 1` ｜ 程序版本 0.1.0 ｜ 解析实现：`src/kumap/core/models.py` + `src/kumap/core/provider.py`

本文档描述**你自己准备/导入**的数据包格式。内置示例数据的生成口径见 `src/kumap/resources/README_data.md`。

---

## 0. 文件放哪里、什么时候生效

| 用途 | 位置 | 说明 |
| --- | --- | --- |
| 点位主文件 | `<数据目录>\import\points_*.json` | 数据目录默认 `%APPDATA%\KuroMapHelper`（便携模式见 README） |
| 路线文件 | `<数据目录>\import\routes_*.json` | |
| 配套底图 | `<数据目录>\import\world_map.png` | 与点位文件同目录时会被自动识别 |
| 官方数据包 | `<数据目录>\import\points_kurobbs_<state>.json` + 同名 `world_map.png` | 由 `tools\fetch_official_map.py` 生成，见第 12 节 |
| 抓取缓存 | `<数据目录>\import\kurobbs_cache\` | 子目录，不参与分片合并；删掉就是重新抓 |
| 点位分片 | `<数据目录>\import\` 下其它 `*.json` | 不以 `routes` 开头的 JSON，其中的 `points` 按 id 合并 |
| 最高优先级 | 设置 → 数据与地图 里手选的「点位数据文件」「大地图底图」 | 覆盖以上全部 |

加载优先级（与代码一致）：

- **点位主文件**：设置指定的文件 → `import\points*.json`（**文件名倒序，只有第一个被找到的是主文件**，
  其余同前缀文件只作为分片参与合并）→ 内置示例 `points.json`。主文件解析失败会直接报错（界面上提示数据不可用），
  不会自动跳过去读下一个文件。
- **分片合并**：再把 `import\` 下其它 `*.json`（不以 `routes` 开头、且不是主文件本身）里的 `points` 按 `id` 合并；
  同一个 `id` **只保留先出现的那一份**，顺序是：
  - 主文件是导入文件 / 手选文件时：`主文件 > 分片 > 内置示例`（内置示例只补 id 没被占用的点位）；
  - 主文件是内置示例时（`import\` 里没有 `points*.json`、也没手选）：`分片 > 内置示例`。
  - 分片之间按文件名**倒序**排列，**排在前面的分片胜出**（文件名带日期时，日期大的赢）。
    元信息（`map` / `source` / `disclaimer`）取自排在最前面的那一份；`layers` / `regions` 按 `key` / `id` 先出现者胜。
  - **所以：不同分片之间不要出现重复 `id`**，否则谁生效取决于文件名，容易看走眼。
  - 分片解析失败会被静默跳过（与主文件不同），坏 JSON 不会让程序报错，只会「悄悄少点位」。
- **路线**：`import\routes*.json`（文件名倒序）→ 内置示例 `routes.json`，按路线 `id` 合并，
  同一个 `id` **以先读到的为准**（与点位同一套口径）：最新的导入包胜出，内置示例只会补没有被占用的 `id`。
  反过来，如果你希望示例路线继续生效，就别让导入包用相同的 `id`。
  解析失败的路线文件同样被静默跳过；设置里没有「路线文件」的手选项，只能靠 `import\` 目录。
- **底图**：设置指定 → 数据包 `map.image` 或数据包同目录的 `world_map.png` → `import\world_map.png` → 内置占位图。

改动数据文件后**需要重启程序**才会重新加载（设置里点「应用/确定」改了路径也会立即重载一次）。

## 1. 坐标定义（先看这条，否则一定错位）

所有 `x` / `y` 都是**归一化坐标**：

```
x = 点位在底图上的像素列 / 底图像素宽度
y = 点位在底图上的像素行 / 底图像素高度
0.0 = 底图左边界 / 上边界，1.0 = 右边界 / 下边界，原点在左上角
```

反算像素：`px = x * width`、`py = y * height`。程序绘制时按**实际载入底图的像素尺寸**换算，
所以只要点位与底图同源，换分辨率不影响对齐。`x` / `y` 超出 `[0,1]` 会被钳到边界值（点位会贴在图边缘，属于数据错误）。

> 站点导出常见的是它自己的像素坐标或 0~100 百分比：像素要除以**那张站点底图**的宽高，百分比除以 100。
> 换算用的宽高必须与你要配的那张底图一致，不要用内置示例的 1536×1024。

## 2. points.json 顶层字段

```json
{
  "schema_version": 1,
  "source": "imported",
  "disclaimer": "数据来源与整理日期：……",
  "map": { "id": "world_map_v1", "name": "大地图", "width": 8192, "height": 5461 },
  "layers": [ { "key": "chest", "label": "宝箱", "color": "#f2b134", "glyph": "diamond" } ],
  "regions": [ { "id": "r1", "name": "荒石坡", "bbox": { "x0": 0, "y0": 0, "x1": 0.25, "y1": 0.5 } } ],
  "points": [ ]
}
```

| 字段 | 类型 | 必填 | 解析行为 / 说明 |
| --- | --- | --- | --- |
| `schema_version` | int | 建议 | 程序当前只认结构，不校验版本号；请填 `1` |
| `source` | str | 建议 | 写入数据集来源标记，界面与 tooltip 会用。约定：`sample` 示例 / `imported` 公开导出 / `official` 官方 / `user` 自建 |
| `disclaimer` | str | 建议 | 数据口径声明，会在「数据与地图」「合规与关于」原样展示，写清出处与游戏版本 |
| `map` | object | 建议 | 底图元信息，见下表 |
| `layers` | array | 可省 | 图层定义；缺省或写不全时，程序用内置 6 类兜底定义（见第 4 节）；出现未知 key 时按灰色圆点显示 |
| `regions` | array | 可省 | 区域划分，用于筛选与路线 `region_ids` 对照 |
| `points` | array | **必填** | 点位列表；没有 `id` 的记录会被**整条丢弃** |

`map` 对象：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | str | 建议 | 底图标识 |
| `name` | str | 可省 | 显示名 |
| `width` / `height` | int | 建议 | 生成坐标时所用的底图像素尺寸；当前版本仅作为元信息记录（渲染以实际底图为准），但**务必填对**，否则你无法判断坐标是谁换算的 |
| `image` | str | 可省 | 底图路径。**注意**：程序把它当作「绝对路径」或「相对内置资源目录」的路径解析，写成 `world_map.png` 这种相对文件名在 `import/` 场景下不会命中；最省事的做法是**不填 `image`，把底图命名为 `world_map.png` 放在数据包同目录** |

## 3. points[] 单条点位字段

| 字段 | 类型 | 必填 | 缺省值 | 解析行为 / 说明 |
| --- | --- | --- | --- | --- |
| `id` | str | **是** | — | 全表唯一、且**跨版本稳定**（完成标记、收藏、云端同步都靠它）。缺 `id` 的条目被忽略 |
| `layer` | str | 是 | `"other"` | 图层 key，见第 4 节；写未知 key 不报错，会以灰色圆点出现在图层列表末尾 |
| `name` | str | 建议 | 取 `id` | 显示名 + 搜索命中字段 |
| `x` | float | 是 | `0.5` | 归一化坐标，钳制 `[0,1]`，建议保留 4~5 位小数 |
| `y` | float | 是 | `0.5` | 同上 |
| `region` | str \| null | 可省 | `null` | 所属 `regions[].id`；程序不做校验，只用于统计与筛选 |
| `level` | int \| null | 可省 | `null` | **只有整数会被采纳**，写成 `"3"` 之类字符串会当成 `null`。约定：`material` 填稀有度 1~3，`echo` 填 COST（1/3/4），其余留 `null` |
| `drops` | array[str] | 可省 | `[]` | 掉落 / 产出，tooltip 最多显示 6 项；非数组按空处理 |
| `note` | str | 可省 | `""` | 数据自带的说明；你在工具里写的备注存在 `markers.json`，优先级高于这里的 `note` |
| `author` | str | 可省 | `""` | 出处/整理者，tooltip 的「来源」行；也是搜索字段 |
| `source` | str | 可省 | `"official"` | 单条来源标记；`private` 是保留值（本机自建点位），**不要**在导入数据里使用 |

## 4. 图层 key（6 类）

| `key` | 中文名 | 默认颜色 | 图标形状 `glyph` | 归类口径 |
| --- | --- | --- | --- | --- |
| `chest` | 宝箱 | `#f2b134` | `diamond` 菱形 | 奇藏箱 / 物资箱 / 藏宝地 |
| `anchor` | 锚点 | `#3ec6c0` | `beacon` 信标 | 小型信标 / 中枢信标 / 传送点 |
| `material` | 材料 | `#66c46a` | `hex` 六边形 | 采集物、矿石、突破材料 |
| `echo` | 声骸 | `#b07de0` | `star` 星形 | 野外声骸巢点 / 声骸 BOSS |
| `puzzle` | 解谜 | `#5b9df9` | `ring` 圆环 | 共鸣方碑、四色灯偶、观景点、隙声蝶、无音区等 |
| `quest` | 任务 | `#f2705b` | `flag` 旗帜 | 纪闻 / 伴星 / 道引 / 危行任务 |

`layers[]` 元素：`key`（必填）、`label`（缺省取内置中文名）、`color`（缺省取内置色，`#rrggbb`）、
`glyph`（缺省取内置形状；不认识的形状按圆点 `dot` 画）。你**可以**声明第 7 个自定义图层（例如 `boss`），
程序会按你给的 label/color/glyph 显示并单独开关。

## 5. routes.json 字段

```json
{
  "schema_version": 1,
  "source": "imported",
  "disclaimer": "路线为转载公开分享，已注明原作者。",
  "routes": [ ]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schema_version` / `source` / `disclaimer` | 同 points.json | 建议 | 路线包与点位包应写同一个 `source` / 出处 |
| `routes` | array | **必填** | 路线列表；缺 `id` 的条目被忽略；不同文件的路线按 `id` 合并，**先读到的文件生效**（见第 0 节） |

单条 `routes[]`：

| 字段 | 类型 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | str | **是** | — | 稳定唯一，收藏（★）按它记录 |
| `name` | str | 建议 | 取 `id` | 列表显示名 |
| `author` | str | 可省 | `""` | 原作者（转载务必保留） |
| `description` | str | 可省 | `""` | 路线说明 |
| `tags` | array[str] | 可省 | `[]` | 标签，如「开荒」「宝箱」 |
| `est_minutes` | int | 可省 | `null` | 预计耗时；**只有整数生效**，小数/字符串按 null |
| `region_ids` | array[str] | 可省 | `[]` | 途经区域 id（按经过顺序去重） |
| `steps` | array | 是 | `[]` | 步骤；程序会按 `seq` **升序重排** |

单条 `steps[]`：

| 字段 | 类型 | 必填 | 缺省 | 说明 |
| --- | --- | --- | --- | --- |
| `seq` | int | 是 | `0` | 从 1 连续递增；重复的 `seq` 靠排序稳定性决定先后，请避免 |
| `point_id` | str | **是** | `""` | **必须存在于点位数据的 `points[].id`**；引用不到的步骤在图上没有坐标，会被跳过（导航时会出现「空站」） |
| `label` | str | 可省 | `""` | 该步要做的事，如「解锁锚点」「清点物资箱」 |
| `note` | str | 可省 | `""` | 该步提示，显示在下一站文案里 |

跨文件约定：路线包里的 `point_id` 依赖点位包里的 `id`，**两份必须同一批导出、同时替换**；
否则收藏、完成标记、同步队列都会错位。首步建议是 `anchor`（信标起步），程序不强制校验。

## 7. 命名规范建议

- 文件名：`points_YYYYMMDD_来源.json`、`routes_YYYYMMDD_来源.json`（**倒序取最新**，所以日期前缀最可靠）。
  想临时停用某个主文件，把它改成不以 `points` 开头（例如 `off_points_20261121.json`）；注意只要它仍以 `.json`
  结尾且不以 `routes` 开头，就仍会被当成分片合并 —— 想彻底停用最省事的办法是把扩展名改成 `.json.bak`。
- 分片文件（按区域拆的）用不带 `points`/`routes` 前缀的名字，例如 `region_r1.json`，会被当作点位分片合并；
  **不要**把分片命名成 `routes_xxx.json`，否则它会被当路线文件、里面的点位不会被合并。
- 分片之间、分片与主文件之间**不要出现重复 `id`**：点位与路线都是「先出现者胜」，而「先出现」由文件名倒序决定，
  看名字很容易判断错。
  合并多个来源时，给 id 加来源前缀（如 `bilibili_chest_0142`）比依赖覆盖顺序稳妥得多。
- 点位 `id`：`{layer}_{4~6位序号}`（与内置示例同风格），或者 `{来源}_{来源原始ID}`（可稳定复现，推荐用于官方导出；
  官方抓取脚本用的就是 `kurobbs_<官方 location id>`，重跑后 id 不变，完成记录不会错位）。
  绝对不要用「按坐标重排生成的序号」——下次重排，你的完成记录和收藏就全错位了。
- 区域 `id`：短码 `r1..rN`；`name` 用公开世界观名称。
- `note` 建议 ≤ 40 字（tooltip 只显示一行起）；掉落/名词用公开中文名，避免生僻自造词，方便搜索。

## 8. 底图与点位同源 / 对齐

必须同时满足三件事，否则点位会整体偏移或缩放错位：

1. **同源**：点位坐标与底图来自同一份导出（同一站点、同一版本、同一张图）。
2. **同尺寸口径**：`map.width/height` 是生成坐标时那张图的像素尺寸；底图若被整体缩放（等比）不影响归一化坐标，
   但被裁剪、加边、拼接、换投影都会失效。
3. **同原点**：归一化以底图左上角为原点；导出方若以中心为原点，需要你先换算成 0~1 左上原点。

自检方法：载入后把某个已知地标（例如你熟悉的一座锚点）放大，看它是否落在真实地形位置上；
若所有点整体朝一个方向偏、或越靠边偏得越多，就是底图/坐标不同源，**不要**在工具里手动挪点，回去换配套底图。

库街区官方 H5 大地图用的是「世界坐标 + 瓦片网格」而不是像素图，本项目已实测并实现该投影（state=8）：

```
S      = 85000.0                        # 世界单位 / 瓦片（与瓦片像素边长无关）
tileX  = floor(X / S) + 1               # 向 -inf 取整
tileY  = -floor(Y / S)                  # Y 越大越靠画面下方
瓦片覆盖：X ∈ [(tileX-1)·S, tileX·S)   Y ∈ [(-tileY)·S, (1-tileY)·S)
拼接：col = tileX - txMin，row = tyMax - tileY（官方对象集合不是矩形，缺片按深色填充）
归一化：x = (X - (txMin-1)·S) / ((txMax-txMin+1)·S)，y = (Y + tyMax·S) / ((tyMax-tyMin+1)·S)
```

自检闭环：官方点 `(936586, 492151)` 必须落在瓦片 `(12, -5)`（残息海岸危行任务）；`unit` 测试见
`tests/test_official_map.py::test_tile_of_matches_official_examples`。自己写转换器时先跑通这两点，再谈批量转换。

## 9. 本机其它 JSON（了解即可，不用手写）

| 文件 | 结构 |
| --- | --- |
| `markers.json` | `{version, updated_at, states: {点位id: {done, updated_at, origin, note}}, pending: {点位id: true/false}}`；`origin` 取 `local` / `remote` / `private`；`pending` 就是待回传队列 |
| `private_points.json` | `{version, updated_at, points: [与 points[] 同构]}`，程序会强制 `source = "private"`、`author = "本机"`，id = `private_` + 10 位十六进制 |
| `favorites.json` | `{version, routes: [路线id]}` |
| `kuro_api.json` | `ApiConfig` 各字段（`authorize_url` / `token_url` / `userinfo_url` / `markers_url` / `push_markers_url` / `points_url` / `routes_url` / `client_id` / `scopes` / `redirect_host` / `redirect_port` / `redirect_path` / `verify_tls`） |
| `config.json` | 界面 / 识图 / 热键 / 图层可见性 / 同步 / 数据路径 / 账号 配置；结构损坏时自动改名 `config.broken` 并回默认值 |

## 10. 如何验证一份数据包

1. **语法**：`python -m json.tool import\points_demo.json >nul`（Windows cmd，无输出即语法正确）。
2. **契约自检**（在项目根目录执行，按需改文件名）：

   ```python
   import json
   p = json.load(open(r"import\points_demo.json", encoding="utf-8"))
   r = json.load(open(r"import\routes_demo.json", encoding="utf-8"))
   ids = [x.get("id") for x in p.get("points", [])]
   assert all(ids), "有点位缺 id"
   assert len(set(ids)) == len(ids), "点位 id 重复"
   bad = [i for x, i in zip(p["points"], ids) if not (0 <= x.get("x", -1) <= 1 and 0 <= x.get("y", -1) <= 1)]
   layers = {"chest", "anchor", "material", "echo", "puzzle", "quest"} | {l["key"] for l in p.get("layers", [])}
   wrong_layer = [i for x, i in zip(p["points"], ids) if x.get("layer") not in layers]
   miss = {s["point_id"] for rt in r["routes"] for s in rt.get("steps", [])} - set(ids)
   print("越界:", bad[:5], "未知图层:", wrong_layer[:5], "路线引用缺失:", sorted(miss)[:5])
   ```

   三行输出都应是空列表。
3. **程序内验证**：设置 → 数据与地图 →「选择…」指到该文件（或直接放进 `import\`）→ 确定 → 重启程序。
   看三处：侧栏「点位图层」各层数量是否符合预期、「探索进度」分母是否等于点位数、
   地图上任一已知地标的位置是否与真实地形对齐。路线则在「探索路线」列表里能看到名字与步数。
4. **回退**：出问题就把 `import\` 里的文件移走（或在设置里清空那两个路径）并重启，即回到内置示例数据。

## 11. 常见错误与对应现象

| 现象 | 原因 |
| --- | --- |
| 点位整体偏移 / 边缘偏移更大 | 底图与点位不同源（尺寸、裁剪或原点不同） |
| 地图上一个点都没有 | 文件名不是 `points*.json` 且设置里也没指定；或主文件 JSON 语法错误 —— 解析失败会直接报 `ProviderError` 并弹窗提示，**不会**自动跳过这个文件（回退路径同样会扫到它）。请把这个文件改名成 `.json.bak` 或修好后重启，原因详情在 `<数据目录>\app.log` |
| 某些点不见了 | 该条缺 `id`（被丢弃） |
| 图层多出一项灰色圆点 | `layer` 写了未定义的 key（不报错，但归类不对） |
| 导航时某一站没有坐标 | 路线 `point_id` 在点位数据里不存在：该站不会被画进轨迹折线，但站数与编号仍按 `steps` 计算，于是编号和线段会错位 |
| 导入的路线看不到、或看到的还是示例路线 | 路线文件名不以 `routes` 开头（会被当点位分片）、JSON 解析失败被静默跳过，或 `import\` 里有多份 `routes*.json`：同 `id` 只有文件名倒序排最前的那份生效 |
| 合并多个分片后点位数对不上 | 分片之间存在重复 `id`：同 id 只保留先出现的那一份，而「先出现」由文件名倒序决定 |
| 完成标记 / 收藏错乱 | 数据更新时点位 `id` 被重排（见第 7 节命名建议） |
| 等级列不显示 | `level` 写成了字符串（只有整数生效） |

## 12. 官方大地图数据包（`tools/fetch_official_map.py` 生成）

脚本只做一件事：把库街区官方 H5 大地图的**匿名公开静态资源**（图片瓦片 + JSON）本地化，
转成本工具的数据包，**不需要账号、不调用任何需要凭据的接口、不碰验证码/滑块**。用法见 README「数据导入」。

产物口径（`points_kurobbs_<state>.json`）：

| 字段 | 来源 / 规则 |
| --- | --- |
| `id` | `kurobbs_<官方 location.id>`：与官方原始 id 一一对应，重跑稳定，因此完成标记与收藏能跨版本沿用 |
| `layer` | 官方目录（`catalog.json`）的**大类**映射到内置图层：`收集物→chest`、`NPC及服务点→anchor`、`采集物→material`、`BOSS`/`强敌→echo`、`挑战`/`探索→puzzle`；语义对不上的大类另开 `k<官方大类id>` 自定义图层，label 用官方大类名 |
| `name` | 官方点位类型名（如「朴素奇藏箱」「残息海岸」），也是搜索字段 |
| `x` / `y` | 由第 8 节投影公式从官方世界坐标换算成归一化值，对齐同批瓦片拼出的 `world_map.png` |
| `world` | **额外保留**官方原始世界坐标 `[X, Y]`（本项目解析器忽略未知字段），改投影或日后与游戏内位置对齐时可直接重算，不必再联网 |
| `official_type` | 官方点位类型 id（`position.json` 里的 `id`），需要按官方细分筛选时用 |
| `region` | `c<countryId>`，`regions[].name` 取官方 `country.json` 的名字（瑝珑 / 黎那汐塔 / 罗伊冰原 / 黑海岸） |
| `level` | 官方 `level`，只在是整数时写入（采集物稀有度、声骸 COST 等） |
| `note` | 官方 `description`；若该点有分层（`floorId`，如 `-1/1`）追加 `[分层 -1/1]` |
| `author` / `source` | 固定 `库街区官方大地图` / `kurobbs` |
| `map` | `width/height` = 瓦片网格 × `--tile-width`；**故意不写 `image`**，让同目录的 `world_map.png` 自动同源生效 |
| `disclaimer` | 官方公开数据声明 + 本项目固定的识图误差免责句 |

数据边界与注意事项：

- 当前 state=8 约 **19249 个点位**（官方 19250 条里剔除 1 个飞点坐标），官方分类共 432 种。
  被剔除的条目记录在 `kurobbs_meta.json` 的 `outliers` 里，不会静默消失。
- 包络范围只统计**有点位的瓦片**，剔除的是「孤立且只有零星点」的飞格（切比雪夫距离 5 格外没有≥3 个点的格子），
  而不是简单的百分位裁剪 —— 后者会把西端 黑海岸、东端 黎那汐塔 这种每格只有几十甚至 2 个点的真内容整列裁掉。
- 点位多≠卡：一帧图标数超过 2400 时画布自动按像素格聚合降级（悬浮/点击仍命中真实点位），
  实测官方包全览一帧约 25ms（见 `tests/test_map_canvas.py`）。
- 瓦片是官方 CDN 的**降采样产物**（`x-oss-process=...,resize,w_N,h_N`），不是原始 1024 素材；
  `--tile-width` 越小越省流量，但超过 1400px 的整图会被识图索引进一步降采样，识别成功率下降。
- 版权：图片与数据归库洛游戏/鸣潮官方所有，仅供个人学习研究，**不得二次分发、不得商用、不得打包进安装包**；
  `import/` 与 `kurobbs_cache/` 都已在 `.gitignore` 中排除。抓取是低频一次性操作，请保留默认 `--delay`。
